# Quality Attribute와 설계 위험 등록부

> 상세 설계 참조입니다. 처음 읽는 부서원은 [전체 → 기능 → 담당 작업 안내](../development/README.md)에서 시작하세요. 아래 초기 설계의 미정/제안과 현재 구현 선택은 [구현 계약](../implementation/contracts.md)을 함께 확인합니다.

## 상태와 적용 범위

RISK-01 등 Source 내부 위험의 구현·검증 주체는 외부 Source 담당자다. DSN은 RPC 경계에서 관측 가능한 현상과 요구 동작을 전달하며 Source 내부 계측·개선 작업을 수행하지 않는다. RISK-04의 중계 구현도 외부 책임이고 RPC session 매핑은 공동 계약이다.

이 문서는 설계에서 도출한 **위험 가설과 관측 아이디어**를 기록한다. 모든 위험의 현재 상태는 `등록 / 미평가`다. 발생 가능성·실제 영향·수치 임계값은 검증되지 않았으며 알려진 구현 결함으로 분류하지 않는다.

현재 수행 범위는 QA 정의, 시나리오·위험·관측 후보 등록이다. 상세 계측·모니터링 구현, 부하 평가, 개선 조치는 **1차 개발 완료 이후**에 수행한다. 어떤 monitoring 제품, 대시보드, 수집 주기, 자동 복구 정책도 이 문서에서 확정하지 않는다.

## QA 시나리오와 모니터링 아이디어

각 항목은 자극, 조건, 대상, 기대 응답과 관측 후보를 구분한다. 관측 후보는 현재 구현 요구사항이나 확정된 지표 schema가 아니다. 후속 평가 task에서 비용과 유효성을 확인한 뒤 선택한다.

### RISK-01. Source 발행 경로 비용

- **자극·조건:** 여러 producer가 발행하거나 탄창이 포화되는 상황, 커널 발행 문맥.
- **대상·기대 응답:** Fire Gun은 전송·연결·자원 여유를 기다리지 않고 적재 또는 폐기로 반환한다.
- **관측 아이디어:** 같은 Source 시계의 Publish 진입·반환 표본, 적재 성공·폐기 수, 호출 경로의 할당·경합 관측. 전송 worker 비용과 호출자 비용을 구분한다.
- **판정 미정:** 환경별 지연 분포·CPU 목표와 표본률. 측정 최대값을 지연 상한 보장으로 간주하지 않는다.
- **후속 검토 후보:** 준비 단계 비용 분리, 사전 할당, batch 등. 채택 여부는 측정 후 결정한다.

### RISK-02. 참조 반환의 정확성

- **자극·조건:** 파싱 실패, 명시적 Checkin 이후 호출 종료, 미반납 후 함수 반환.
- **대상·기대 응답:** 각 lease는 한 번만 유효 반납되고 원본은 마지막 참조에서 회수된다.
- **관측 아이디어:** 테스트용 root/lease ledger, 개발용 미반납 참조 목록, Checkout/Checkin 차이, 살아 있는 원본 수. 운영에서는 필요 시 표본 추적을 검토한다.
- **1차 구분:** T07–09의 정확성 검증과 결함 수정은 현재 기능 범위다. 운영 추적 저장소·알림·장기 보유 탐지는 후속 범위다.
- **후속 검토 후보:** 추적 표본과 보존 범위 조정. timeout만으로 활성 원본을 재사용하는 조치는 후보에 포함하지 않는다.

### RISK-03. 순차 실행과 root 보유

- **자극·조건:** 한 Workspace 파싱 또는 Append가 늦어지고 입력은 계속 들어온다.
- **대상·기대 응답:** 순차 실행과 유효 참조를 유지하며 자원 초과는 정의된 폐기 동작으로 처리한다.
- **관측 아이디어:** 큐 깊이·보유 bytes, Workspace 처리 구간, Append 구간, Workspace lease 보유 시간과 원본 전체 수명을 분리한 표본. 여러 값의 동시 변화를 비교한다.
- **판정 미정:** 허용 backlog, 원본 보유 시간, 수용 가능한 손실 수준.
- **후속 검토 후보:** 실행 방식 변경, 저장 인계 분리, batch 처리. Workspace별 큐나 병렬 실행을 현재 기본값으로 추가하지 않는다.

### RISK-04. Source 단위 실패 격리

- **자극·조건:** 중계 session 하나에 여러 source_id가 있고 그중 하나에서 심각 오류가 발생한다.
- **대상·기대 응답:** 대상 Source만 종료하고 다른 Source의 정상 경로를 유지한다. 새 attach는 허용한다.
- **관측 아이디어:** 논리 Source↔session 매핑, 종료 이유·대상, 다른 Source의 수신 지속 여부, 반복 attach 횟수. 검증 전 source_id와 실제 연결 식별자를 구분한다.
- **1차 구분:** 매핑과 주입된 판정에 따른 종료 기능은 F-02·E-03에서 검증한다. 실제 운영 자동 판정·차단 조정은 이후다.
- **후속 검토 후보:** 중계의 논리 차단과 연결 구조 조정. 물리 연결 전체 종료를 해당 Source 종료와 동일시하지 않는다.

### RISK-05. 오류 집계 포화

- **자극·조건:** 동일 오류가 폭주하거나 서로 다른 오류 본문이 계속 생성된다.
- **대상·기대 응답:** 같은 본문은 count로 집계하고 Admin 미가동 상태에서도 오류 접수 경로가 독립적으로 동작한다.
- **관측 아이디어:** Report 입력 수, 고유 집계 항목 수·보유 bytes, 접수 실패 수, Admin 전달 지연. 같은 포화 경로에 관측 이벤트를 재투입하지 않는 수집 방법을 검토한다.
- **판정 미정:** 집계 보존·경고 기준·운영 fallback. 기본 유한 한도와 재귀 방지는 E-01의 1차 기능 계약이다.
- **후속 검토 후보:** 보존 기간·snapshot 빈도 조정. 오류 동일성 필드를 임의로 줄여 다른 오류를 합치는 변경은 별도 계약 검토가 필요하다.

### RISK-06. 종료 지연

- **자극·조건:** 종료 요청 시 Workspace·Append·View query가 진행 중이고 일부가 반환하지 않는다.
- **대상·기대 응답:** 새 입력을 막고 미실행 root를 정리하되 활성 호출이 사용하는 자원을 회수하지 않는다.
- **관측 아이디어:** 종료 단계, 미종료 호출·query 수, 잔여 root/lease, 단계별 경과 시간, flush 상태.
- **1차 구분:** 시작·종료 순서와 미완료 상태는 H-01·H-02에서 정의·검증한다. 운영 timeout 조정·자동 프로세스 조치는 이후다.
- **후속 검토 후보:** 협력 취소와 종료 시간 설정 조정. 진행 중 원본의 강제 재사용은 허용하지 않는다.

### RISK-07. 데이터와 지연 해석

- **자극·조건:** Source 간 시계 차이, 전송 전 손실, 저장 접수와 영속 완료의 차이, View 조회 시점 차이.
- **대상·기대 응답:** 측정 지점과 저장·조회 보장 범위를 구분하고 사용자에게 정의된 View 결과를 제공한다.
- **관측 아이디어:** 발행·수신·저장 계수의 범위 표시, 저장 접수/완료 시점 구분, query의 데이터 가시성 정보. 없는 Source 계측을 수신 건수로 대체하지 않는다.
- **판정 미정:** 조회 최신성 목표와 지연 측정 범위. 서로 다른 clock의 값을 직접 뺀 수치를 성능 지표로 사용하지 않는다.
- **후속 검토 후보:** 결과 메타데이터 보강이나 필요 시 추가 상관관계 정보. ACK·전역 정렬·exactly-once를 기본 기능으로 추가하지 않는다.

### RISK-08. 버전과 계약 호환성

- **자극·조건:** 지원하지 않는 envelope 또는 plugin 버전, record field 규격 변화.
- **대상·기대 응답:** 정의된 범위에서 수락·거부하고 실패를 식별 가능하게 남긴다.
- **관측 아이디어:** 거부된 버전별 건수, 시작 시 plugin 목록과 계약 버전, query field 오류의 구분.
- **1차 구분:** 공통 fixture와 부적합 plugin·field 테스트는 F/I/H/V 기능 검증이다. 장기 추이·배포 모니터링은 이후다.
- **후속 검토 후보:** 호환 matrix 확장, 배포 전 대조 절차. hot reload는 이 위험 등록으로 추가하지 않는다.

### RISK-09. 계측 overhead

- **자극·조건:** Source별·Workspace별 상세 추적을 활성화한다.
- **대상·기대 응답:** 관측 비용과 시스템 본래 비용을 구분할 수 있어야 한다.
- **관측 아이디어:** 같은 workload에서 계측 비활성/최소/상세 설정 비교, 표본률별 지연·CPU·메모리 변화.
- **판정 미정:** 허용 overhead와 수집 주기. 모든 메시지를 동기 logging하는 방식을 전제하지 않는다.
- **후속 검토 후보:** sampling·집계·수집 위치 조정. 구체 도구와 exporter는 아직 선택하지 않는다.

## 후속 평가와 상태 관리

| 시점 | 수행 내용 | 상태 변경 |
| --- | --- | --- |
| 현재 | QA·위험·관측 후보 등록, 기능 계약과 연결 | 등록 / 미평가 |
| 1차 완료 후 평가 준비 | 환경·목표·workload·표본·도구 결정 | 평가 계획 확정 |
| 실제 평가 | 관측 구현과 비교 실행, 원시 결과 기록 | 평가 완료 — 영향 확인 또는 관측 범위에서 미확인 |
| 조치 검토 | 필요성과 trade-off 검토, 후속 작업 정의 | 조치 제안 또는 현 구조 유지 |
| 조치 후 | 같은 조건으로 재검증 | 잔여 위험 기록 / 종결 근거 기록 |

작은 workload에서 문제가 관측되지 않았다는 이유만으로 위험을 제거하지 않는다. 위험당 근거·환경·측정 범위·후속 결정을 남긴다. 현재는 자동 조치나 상세 monitoring 구현 task를 새로 생성하지 않는다.

기존 F-06은 QA·관측 아이디어 정리 범위로 제한한다. E-02와 X-04는 1차 완료 이후로 이동하고, X-05의 1차 산출물 인수는 이 후속 평가를 기다리지 않는다. 상세 작업 분해는 그 시점에 수행한다.
