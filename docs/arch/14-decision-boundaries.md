# 담당자 결정과 경계 계약 협의

## 판단 기준

Source 내부 구현은 외부 Source 담당자가 결정한다. DSN은 RPC 계약·서버·Mock에 집중하며 Source 내부 API·탄창·메모리·kernel/eBPF·중계 구현 방식의 협의를 요구하지 않는다. RPC 경계가 바뀌는 경우에만 해당 Source 담당자와 호환성을 협의한다. S/K 표기는 DSN 구현 track이 아닌 외부 담당을 뜻한다.

**다른 모듈이 의존하는 계약과 실행 조건을 유지하는 구현 선택은 담당자가 결정한다. 계약·소유권·관측 가능한 동작·배포 조건이 달라지는 선택은 영향을 받는 제공자와 소비자가 협의한다.** 같은 track 안에서도 담당 모듈이 다르면 이 기준을 적용한다.

Track 이름은 기술 영역을 식별한다. F track은 공통 계약의 기록 위치이며 모든 결정을 집중하는 별도 승인 조직이 아니다. 협의 대상은 변경의 직접 영향 범위로 제한한다. 이미 정해진 계약을 구현하는 작업은 매번 다시 협의하지 않는다.

| 구분 | 담당자 결정 | 경계 계약 협의 |
| --- | --- | --- |
| 코드 구조 | 모듈 내부 클래스·함수·파일 분할 | 공개 API·공통 타입·패키지 의존성 변경 |
| 자료구조 | 계약을 지키는 내부 표현과 알고리즘 | FIFO·동시 호출·소유권·메모리 수명 변경 |
| 자원 사용 | 정해진 예산·설정 범위 안의 pool·batch 구현 | 최대 입력 크기·공개 용량 설정·포화 결과·새 worker 도입 |
| 실패 처리 | 정해진 실패 결과를 만드는 내부 흐름 | 예외 전파·재시도·반납·부분 성공·후속 대상 처리 의미 변경 |
| 데이터 | 공통 스키마를 구현하는 내부 mapping | wire·record·query·오류 필드의 이름·타입·의미 변경 |
| 검증 | 대역·테스트 구조·내부 fixture 생성 방식 | 공통 fixture의 기대 결과·지원 환경·완료 기준 변경 |
| 도구·의존성 | 공통 build와 배포에 영향을 주지 않는 로컬 도구 | DSN 공통 toolchain·배포 의존성·권한·endpoint 변경 |

담당자 결정도 해당 task의 코드·검증·산출물에 남긴다. 별도 협의 문서를 모든 내부 선택에 요구하지 않는다. 협의가 필요한 경우 기존 계약과 달라지는 부분, 영향을 받는 소비자, 기대 결과를 함께 기록한다.

표의 협의 대상은 모든 변경에서 전원이 참여한다는 뜻이 아니다. 예를 들어 Decoder의 내부 루프 수정은 I 담당자 결정이며, wire format을 바꾸는 경우에 S/K와 협의한다. 내부 저장 index 변경은 P 담당자 결정이지만 record 타입이나 조회 가시성을 바꾸면 해당 소비자와 협의한다.

## 이미 고정된 기준

[D01–D26](05-decisions.md)는 현재 구현의 기준이다. Source no blocking/no error/no exception, payload 블랙박스, FIFO/no_policy, 기본 순차 실행, 명시적 Checkout·Checkin, View의 Persistence 경유를 각 구현 담당자가 다시 선택하는 항목으로 두지 않는다.

이 기준을 바꾸는 제안은 내부 구현 결정 범위를 벗어난다. 영향을 받는 계약·시퀀스·task·QA를 정리하여 공통 설계 변경으로 다룬다. 미정 사항은 해당 F/A/H/V 결정 task에서 닫는다. QA 상세 monitoring과 개선 조치를 1차 이후로 둔 범위도 유지한다.

## 협의 완료 기준

1. 제공자·소비자가 사용하는 API·데이터·소유권·실패 결과가 한 문서 또는 계약 코드에 일치한다.
2. 정상·실패 예제나 공통 fixture에 기대 결과가 기록된다.
3. 영향을 받는 task와 문서에 선택 결과를 반영한다. 기존 선행 조건과 충돌하면 작업 색인도 갱신한다.

의견 교환만 했다는 사실을 계약 완료로 간주하지 않는다. 공통 fixture가 확정되면 소비자는 실제 제공자 구현을 기다리지 않고 대역으로 진행할 수 있다. 계약에 영향 없는 내부 구현까지 협의 완료를 기다릴 필요는 없다.

## 결정 기록 최소 형식

```text
대상 task / DC ID:
담당자 결정 또는 경계 계약 협의:
선택한 내용과 이유:
영향받는 제공자·소비자 및 계약:
기대 결과 / fixture:
반영 문서·코드 위치:
남은 미정 사항:
```

실제 담당자 이름은 task를 맡을 때 기록한다. 현재 문서는 track별 기술 경계만 지정하며 인원 배정이나 별도 회의·승인 단계를 추가하지 않는다.

## Task 문서 적용

각 task에는 **담당자 결정**, **협의 조건**, **협의 대상·관련 경계**를 표시한다. 협의 조건에 해당하는 새 결정이나 변경이 없으면 기존 계약에 따라 진행한다. E-02·X-04의 분류는 후속 작업을 위한 기록이며 착수 시점을 앞당기지 않는다.
