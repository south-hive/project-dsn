# Source와 DSN Mock

## Source 지원 — 확정

| 대상 | 지원 방향 |
| --- | --- |
| CentOS 9 C++ 앱 | 원 프로젝트에 연결할 Source 라이브러리 제공 |
| Linux 커널 드라이버 | 커널 실행 환경에 적합한 발행 API와 전송 경로 제공 |
| eBPF를 통한 발행 | eBPF 발행 지점부터 DSN 입력까지 이어지는 경로 지원 |

Source API의 공통 의미는 fire gun 탄창에 메시지를 적재하고 즉시 반환하는 것이다. no blocking / no error / no exception은 Source 호출자에게 제공하는 계약이다. 연결이나 전송 실패에 대한 복구 책임을 원 프로젝트에 넘기지 않는다.

커널 및 eBPF 경로는 C++ 사용자 앱의 구현을 그대로 사용하는 것으로 가정하지 않는다. 커널 버전, 실행 문맥, 사용 가능한 버퍼와 사용자 공간 중계 여부를 확인한 뒤 환경별 adapter를 설계한다. 정확한 OS 배포판 식별과 커널 버전도 구현 전에 확인한다.

## 탄창과 전송 경로 — 제안

```text
원 프로젝트
  → 환경별 메시지 준비 API
  → Fire Gun 적재 API
  → 넉넉한 로컬 탄창
  → 별도 전송 실행 흐름 / 필요 시 사용자 공간 중계
  → 컨테이너 경계
  → 실제 DSN 또는 DSN Mock
```

연결 수립, 재연결, 실제 송신은 호출자의 발행 경로와 분리한다. 탄창 적재가 불가능하면 즉시 폐기한다. 초기화 실패와 미연결 상태에서도 발행 호출이 대기하거나 실패를 전파하지 않도록 한다.

탄창의 데이터 소유권은 구현 전 결정해야 한다. 호출자 메모리를 단순 참조하면 함수 반환 후 유효 수명이 보장되지 않는다. 탄창에 복사하거나, 사전 할당한 슬롯을 Source가 채우고 소유권을 인계하는 방식 등을 비교한다. Source 탄창 적재는 DSN 내부 no-copy 계약의 적용 범위 밖이다.

탄창 용량, 최대 메시지 크기, producer 동시성, 적재 연산 및 직렬화 비용, 전송 기술은 미정이다. 후보 비교 시 평균값만이 아니라 발행 호출 지연 분포, CPU 사용량, 메모리 한도, 손실률을 측정한다. polling·batching·전용 스레드는 확정하지 않는다.

## DSN Mock

Source 개발자가 전체 DSN과 업무용 Workspace를 준비하지 않고도 자신의 메시지 발행을 확인할 수 있도록 간단한 console echo 수신기를 제공한다.

### 최소 기능 제안

- 실제 DSN과 같은 Source 측 전송 계약 및 envelope 버전을 수신한다. Source의 수신 대상 설정을 바꾸어 Mock으로 연결할 수 있게 한다.
- 버전별 envelope 구조 검증 코드를 가능한 한 실제 Ingress와 공유하여 Mock만 통과하는 별도 규약이 생기지 않게 한다.
- envelope 필드, payload 길이, payload의 원시 바이트 표현을 console에 출력한다. payload를 업무 스키마로 해석하지 않는다.
- 임의 바이너리를 안전하게 표시하기 위한 기본 표현으로 hex를 제안한다. 길이 제한으로 출력을 생략하면 전체 길이와 생략 여부를 표시한다. 구체 출력 형식과 기본 제한은 미정이다.
- 잘못된 envelope 및 Mock 내부 수신·출력 폐기를 진단 정보로 표시한다. Source에 ACK/NACK이나 처리 오류 응답을 요구하지 않는다.
- Workspace 플러그인, Persistence, View 없이 실행할 수 있게 한다.
- 실행·종료 방법, 연결 설정, C++ 예제, 커널/eBPF 경로의 사용 절차를 제공한다. 실제 명령은 전송 기술과 패키징 결정 후 작성한다.

Mock은 실제 kernel/eBPF 경로에 중계가 필요하면 그 중계를 통해 메시지를 받는다. Mock이 커널에서 직접 호출되는 프로그램이라고 가정하지 않는다.

### Console 부하 처리 제안

console 출력은 느릴 수 있으므로 수신과 출력을 분리하고 출력 대기량에 한도를 둔다. 초과 시 출력 항목을 버리고 누적 폐기 건수를 표시한다. 출력 혼잡이 Source 발행 호출의 대기로 이어지지 않도록 실제 전송 경로와 함께 검증한다.

Mock은 연결·형식·발행 여부를 확인하는 도구다. console 출력 성능을 실제 DSN 처리 성능으로 해석하지 않는다. C# console 프로그램을 우선 제안하며, 호스트 실행과 Docker 실행의 제공 범위는 후속 결정한다.

## 필수 확인 시나리오

| 상황 | 확인 결과 |
| --- | --- |
| C++ Source가 정상 메시지 발행 | Mock에 envelope와 payload 바이트 표현 표시 |
| 서로 다른 바이너리 payload | 특정 스키마 가정 없이 echo 가능 |
| 커널 드라이버 / eBPF 경로 발행 | 지정된 중계·전송 경로를 거쳐 Mock에서 확인 가능 |
| 수신기가 없거나 중간에 종료 | 원 프로젝트의 발행 호출이 연결이나 전송 완료를 기다리지 않음 |
| 탄창 또는 출력 큐 포화 | 대기 대신 폐기; 출력 가능한 시점에 관측 가능한 폐기 정보 표시 |
| 잘못된 envelope 버전·경계 | Mock에서 진단; Source의 호출 경로로 예외를 전파하지 않음 |
